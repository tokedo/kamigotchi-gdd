# GDD Accuracy Audit — 2026-07-05

Full verification of the GDD against the Kamigotchi source repo, run by 12
parallel audit agents (9 mechanics domains, 2 scripted catalog diffs, 1
coverage/completeness sweep). Every formula was recomputed symbolically against
code (not comments); every catalog row was compared field-by-field.

## Baseline

| | |
|---|---|
| GDD pinned commit | `91f69796` (synced 2026-06-15) |
| Source `main` HEAD at audit time | `79b2cf36` |
| Drift | **1 commit, client-only** (`packages/client` modal positioning). `git diff` over `packages/contracts/` between pin and HEAD is **empty**. |

The GDD pin is effectively current; every finding below is an extraction
accuracy issue, not staleness.

## Verdict

- **Catalogs: excellent.** Quest CSVs (4 files, 192 quests), skills, factions,
  and dialogue CSVs are byte-identical to source. Recipes (41), rooms (70),
  nodes (64), scavenge droptables (50), item droptables (6), listings (19),
  bodies/hands/colors traits: exact field-level matches. Main catalog issues
  are in README summary tables and one invented trait field.
- **Mechanics: broadly accurate, with ~35 ERROR-level findings** concentrated
  in a few files (kill.md, token-portal.md, items.md/droptables.md,
  death-revival.md/naming.md, math-random.md/flags.md). Most files' formulas,
  configs, and flows verified exactly. `crafting.md`, `sacrifice.md`,
  `cooldowns.md`, `affinity.md`, `npcs.md` had zero findings.
- **Coverage: no dangling references** (all 152 cited `.sol` files exist).
  Three genuine gaps (Onyx respec, room-gate instances, LibData).
- **Two findings are candidate live bugs in the source repo itself** — worth
  reporting upstream (see § Upstream).

Severity legend: **E** = ERROR (GDD contradicts code/data) · **O** = OMISSION
(material fact missing) · **M** = MINOR (stale line refs, cosmetic) ·
**U** = UNCERTAIN.

## High-impact errors (fix first)

These change how a reader would model the game:

1. **E — Tax units off by 100×** (`mechanics/economy/harvesting.md:42,283–285`):
   tax rate is **basis points** (`rate/1e4`, `LibTax.sol:14,92`), capped at
   2000 bp = 20% (cap unmentioned). GDD says "%".
2. **E — Salvage/spoils are NOT capped at 100%** (`mechanics/combat/kill.md:202,219`):
   the clamp `ratio/precision > 1` only fires at ≥2× precision (integer div).
   Attacker Power 56–154 → 101–199% spoils uncapped; salvage ratio in
   (1000,1999] → `bounty − salvage` **underflows and the liquidation reverts**
   (victim effectively unliquidatable). Code: `LibKill.sol:236,254`,
   `HarvestLiquidateSystem.sol:58`.
3. **E — 0 HP ≠ death** (`mechanics/core-kami/death-revival.md:8,14,29–31`,
   `health-healing.md:11`): `kill()` is called only from liquidation and
   sacrifice. A harvesting Kami drained to 0 stays `HARVESTING` (liquidatable),
   it does not die.
4. **E — Dead Kamis CAN use items; revive items are an undocumented second
   revival path** (`death-revival.md:41–44`): `KamiUseItemSystem` has no
   state/health check; items 11001–11004 (Red Ribbon Gummy +10 HP, Melkarth
   +50, Djed Pillar +5, Pale Potion +75) *require* `STATE == DEAD`.
5. **E — Dropping a non-repeatable quest DOES reset acceptance**
   (`mechanics/progression/quests.md:173–174`): drop erases the instance's
   EntityType → quest can be re-accepted and re-completed for rewards
   (`LibQuest.sol:97–104,338–345`, `QuestAcceptSystem.sol:33`). The file's own
   ⚠️ UNCERTAIN note suspected exactly this.
6. **E — Naming is neither one-time nor free** (`mechanics/core-kami/naming.md:9–21`):
   `useNameable` has zero callers (dead code); naming is repeatable without
   limit and costs 1 Holy Dust every time.
7. **E — Droptable odds are exponential, not linear**
   (`mechanics/economy/droptables.md:24–25,81–82`; also affects
   `creation.md:70–75` trait rolls and `sacrifice.md:87`): weight =
   `2^(w−1)` per `LibRandom.calcRarityWeight` — each +1 tier doubles the odds
   (tier 9 = 256× tier 1).
8. **E — Item-use effect pipeline documented from dead code**
   (`mechanics/economy/items.md:77–86`): `applyStats`/`applyMove`/
   `droptableCommit` have zero callers. Real path: use systems →
   `applyAllos` → `LibAllo.distribute`. Related: stat consumables map
   shift→shift/sync→sync — `LibStat.add` discards the delta's `base`
   (`items.md:80–81` wrong); lootboxes roll via the `ITEM_DROPTABLE` allo with
   the **allo ID** as droptable source (`droptables.md:92–94` wrong).
9. **E — Token portal unit conversion** (`mechanics/marketplace/token-portal.md:141–144`):
   exponent is `10^(18−scale)`, not `10^scale` (`LibERC20.sol:42–52`). ONYX
   (scale 2): 1 game unit = 10^16 wei. Also **E**: receipts do NOT survive
   un-registering a token — claim reverts on unset item
   (`TokenPortalSystem.sol:88–89`); only `setItem` migration preserves claims
   (`token-portal.md:76–81` wrong).
10. **E — Scavenge/collect conflation** (`harvesting.md:59,77,342`,
    `droptables.md:96–99`): collect/stop only **increments the scavenge bar**;
    rolls happen in a separate `ScavengeClaimSystem` transaction
    (`floor(points/tierCost)`, remainder carries).
11. **E — Recoil-efficacy nudge double-discounted** (`kill.md:140,170`): code
    passes raw `config[0]` (=1000), no `/10^config[1]` (`LibKill.sol:210,218`);
    as written the nudge would be ~1 instead of 1000 against ±1000 shifts.
    Also **E** (`kill.md:82–87`): THRESHOLD_RATIO bonuses enter via the
    `up`/`special` shift slots only — zero effect on neutral/disadvantaged
    matchups. Also **E** (`kill.md:176`): recoil strain =
    `calcStrain(killer, spoils)` — scales with loot taken, not the attacker's
    own harvest output.
12. **E — faces.csv invents affinities** (`catalogs/traits/faces.csv` rows
    31–35: Wassie, Jiangshi Hat, Sunglasses, Nerd, Third Eye): GDD says
    `Normal`, source is **empty** (deploys as empty string, not NORMAL).
    Source truth: faces = 16 Normal / 6 Eerie / 5 Insect / 4 Scrap / 5 none.
13. **E — XP table off by one from L4** (`mechanics/core-kami/experience-leveling.md:69`):
    L4 cost is `floor(40×1.259³) = 79`, not 80; cumulative L4–L10 =
    232, 332, 458, 617, 817, 1069, 1386.
14. **E — Energy Drink / UPON_COOLDOWN_SET mismatch**
    (`mechanics/combat/bonus-system.md:93,97–99`): deployed catalog registers
    Energy Drink's buff with terminator `UPON_HARVEST_ACTION`
    (`data/items/allos.csv:11`); **no deployed bonus uses UPON_COOLDOWN_SET**
    — the reset hook currently clears nothing. (See § Upstream for the related
    equipment-bonus data bug.)
15. **E — MINT_START_PUBLIC** (`mechanics/gacha/gacha.md:176`): prod config
    sets it to `1746086400` via `initProdConfigs` (not 0), and 0 would mean
    *always open*, not disabled (gate is `timestamp < start`).

## Notable omissions

- **Liquidation** (`harvesting.md`, `kill.md`): killer account receives
  1 Obol; salvage → victim *account inventory* as MUSU + victim Kami XP =
  salvage; spoils → killer's **harvest balance** (must still be collected, then
  passes killer's tax/XP path); LIQUIDATE score +1; killer must share the
  node's room; victim harvest must be ACTIVE.
- **Kami state model** (`health-healing.md:17–27`, `creation.md:41`): fifth
  live state `LISTED` omitted (internally inconsistent with kami-send.md).
- **Item transfer auth** (`item-usage.md`): `ItemTransferSystem` requires the
  **owner wallet** signature (all other item systems use operator).
- **Disabled items** (`items.md:99`): account-use path never checks
  `verifyEnabled` — disabled ACCOUNT-shaped items remain usable.
- **Cast** (`item-usage.md:47–59`): reverts unless target has an active
  harvest; own Kami is a valid "ENEMY_KAMI" target (no ownership check).
- **Equipment** (`equipment.md:9–10`): account equip is unreachable — only
  caller is KamiEquipSystem; slot prefix never validated.
- **Gacha** (`gacha.md:55–80`): reveal impossible in commit block (blockhash=0
  → revert); effective window [commit+1, commit+256]. **Stake** sets
  State→RESTING (`erc721.md` stake flow).
- **Kami market** (`kami-market.md`): admin can cancel any order
  (`executeAdmin`); accept-offer runs a soulbound check (blocks 3-day
  newbie-vendor Kamis).
- **Skills respec** (`skills.md:139–154`): Kami respec has NO resting
  requirement (check sits in the account branch, where it always reverts —
  accounts lack StateComponent).
- **Allocations** (`allocations.md:45–52`): unmatched-allo skip
  (`alloIDs[i]==0 → continue`) undocumented. **Scavenge claims**
  (`scavenging.md:73–74`): BONUS/CLEAR_BONUS allos apply once, not × tier
  count.
- **Day/night** (`day-night-cycle.md:29–33`): replace invented examples with
  the real uses — `PHASE` condition type and per-phase logging keys
  (`LIQ_WHEN_`, `HARVEST_TIME_`, `HARVEST_WHEN_{PHASE}`).
- **Soulbound** (`soulbound.md:44–52`): missing
  `KamiMarketAcceptOfferSystem` enforcement point.

## Upstream — candidate bugs in the SOURCE repo (report to Asphodel)

1. **Equipment bonuses likely broken in deployed data**: catalog registers
   equipment bonuses under the `USE` use case with bare terminator
   `UPON_UNEQUIP` (`deployment/world/state/items/allos.ts:64`), but equip reads
   the `EQUIP` use-case anchor and generates `UPON_UNEQUIP_{slot}` end types
   (`LibEquipment.sol:48,121–124,277`). Tests pass only because they register
   `EQUIP` + suffixed terminators directly. Net effect: catalog equipment
   bonuses would neither attach on equip nor clear on unequip.
2. **Salvage underflow revert** (see high-impact #2): for salvage ratios in
   (1000, 1999], `bounty − salvage` underflows and liquidation reverts —
   certain victims cannot be liquidated at all.
3. Minor quirks: `FriendRequestSystem.sol:37` checks state `"FRIENDS"` vs
   stored `"FRIEND"` (reverts via wrong branch, same outcome);
   `SkillRespecSystem` RESTING check sits in the account branch (account respec
   always reverts; Kami respec skips the RESTING gate);
   `AccountUseItemSystem` skips `verifyEnabled`.
